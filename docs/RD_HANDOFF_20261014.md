# 119番通報ASR：現行モデル、これまでの試行、残る課題

作成日：2026年10月14日。R&D向けの引き継ぎ資料。数値は、特記しない限り同じ実通報174通話のGold v3.2採点に基づく。**現行の汎用比較基準**は `quality_full_then_human_replay` とする。東京住所向けの後続候補と、入力間隔を変えた推論方式は別に扱う。

## まず押さえる結論

- 現行チェックポイントは、Whisper large-v3を以前の人手教師で適応した`c37`から、GPT-4o自動文字起こし**12,232通話**で1エポック、人手文字起こし**1,186通話**でさらに1エポック学習したもの。元資料14,514通話の全件を学習したわけではない。人手1,186通話には新規797通話と旧教師の再投入389通話が含まれる。
- 学習から除外した実通報126通話では、0.5秒入力時のCERは**20.268%**。同条件で通話学習なし39.233%、自動教師段階28.869%、旧`c37`21.275%。自動教師だけの段階は`c37`より悪く、最後の人手教師段階で大きく回復した。
- **同じ重みのまま**入力を1秒ごとにするとCERは**19.663%**、2秒ごとでは20.072%、全通話オフラインでは20.659%。この126通話では1秒入力が最小値だが、1秒方式の実時間表示遅延・多数通話同時処理は、この比較だけでは保証できない。
- 現行0.5秒評価の21,348誤りは、置換6,737、脱落7,111、挿入7,500。特定の語だけを直せば解決する状態ではない。住所・数字の表記、短い語の脱落、近音語などが模擬通報で観測され、過去の実通報候補では長い挿入も発生した。
- 後続の東京住所向け重みは、同じ126通話で20.239%と30文字だけ良かった。ただし、以前から結果を見ている集合を候補選定にも使用し、実際の東京119通報の住所で独立評価していない。汎用モデルを置き換える根拠としては弱い。

## 1. 現行モデルの構造と学習来歴

| 層 | 内容 |
|---|---|
| 音声入力 | 16 kHz音声をWhisperの128-bin log-Melへ変換。長尺は内部で窓に分けて処理する。 |
| 基盤モデル | Whisper large-v3、encoder・decoder各32層、隠れ次元1,280、各層20 attention head、語彙51,866。日本語の逐次文字列を自己回帰的に生成する。 |
| 事前適応 | 以前の人手教師で学習した`c37`系統。ゼロショットlarge-v3と、自動教師段階・最終段階は連続した学習系統ではない。 |
| 今回の学習 | 既存のencoder・decoder attentionのQ/V LoRAを継続更新。rank 32、alpha 64、dropout 0.05。自動教師段階と人手教師段階は各1エポック、batch 4、seed 42。学習率は順に`2e-6`、`5e-6`。学習時はteacher-forced損失を使用。 |
| 配布重み | LoRAを基盤重みへ統合したnative FP16 `model/whisper.pt`。推論にLoRAアダプターの別読込は不要。SHA-256：`8a8a65377c50c339aba765756b174e0069441c0649f6207f100f2f59aec0a466`。完全なfrozen bundleは別途必要。 |
| ストリーミング | SimulStreaming + AlignAtt + Silero VAC。0.5秒ずつ厳密に入力、beam 3、frame threshold 75、最大音声文脈30秒、最大文字文脈64 token。VAC閾値0.5、無音500 ms、前後パディング100 ms。選定済みの8 alignment headを使用。 |
| 複数通話 | 一つの重みを共有し、通話ごとに音声・VAD・デコーダー状態を保持。可変長デコーダー一括処理を使う評価では10通話を1群として再生した。 |

推論設定の正本は[`models/quality_full_then_human_replay/STREAMING_CONFIG.json`](../models/quality_full_then_human_replay/STREAMING_CONFIG.json)。完全なbundleの要件は[モデル利用ガイド](model_access.md)。**0.5秒は音声を投入する間隔であり、発話から確定文字が表示されるまでの遅延ではない。**

### 教師データの品質と分割

自動文字起こしの教師本文はGPT-4o由来で、Chirp3の本文は教師同士の一致度による品質判定にのみ使用した。候補14,514通話のうち、適格な時刻付き区間を持ち、評価通話と重ならない12,232通話・100,801区間・498.23時間が実学習量。人手段階は1,186通話・6,258区間・45.92時間。人手で「使用可能」とされた1,419通話の全件が最終学習に入ったわけではない。開発48通話と評価用126通話は、今回の両段階の学習から通話単位で除外した。

学習用人手通話1,272件では、GPT-4o/Chirp3の全文一致度とGPT-4o/人手Gold誤りのPearson相関が**−0.797**だった。一致度の低い第1十分位の平均教師誤り42.70%に対し、高い第10十分位は15.84%。一致度は有効な品質の手掛かりだが、教師の正しさを保証しない。音声窓の時刻境界と教師文の対応も別に検証する必要がある。

## 2. 比較可能なCERと読み方

主要指標はGold v3.2の**masked micro CER = 全通話の文字置換＋脱落＋挿入 ÷ 既知の正解文字数**。NFKC、カタカナ→ひらがな、空白・句読点の除去を適用する。数字と漢数字、異なる漢字表記は原則として誤り。正解が不明と注記された区間は所定の上限内で吸収する。評価用126通話の分母は105,331文字。

| 方式・評価用126通話 | 通話学習なし | 自動教師段階 | 現行の人手教師追加後 |
|---|---:|---:|---:|
| 0.5秒入力 | 39.233% | 28.869% | **20.268%** |
| 1秒入力 | 31.597% | 26.008% | **19.663%** |
| 2秒入力 | 29.674% | 24.619% | **20.072%** |
| 全通話オフライン | 31.283% | 26.636% | **20.659%** |

0.5秒での最終段階と自動教師段階の差は**−8.601ポイント**で、通話単位ペア・ブートストラップ95%区間は−12.093～−5.816ポイント。旧`c37`との差は**−1.007ポイント**、同区間は−2.049～−0.102ポイント。旧`c37`に対して126通話中66通話で改善、56通話で悪化、4通話で同数だった。平均の改善は、全通話での無悪化を意味しない。自動教師段階の28.869%は旧`c37`の21.275%より**7.594ポイント悪い**ため、人手段階の大きな改善には自動教師段階で失った性能の回復分が含まれる。

1秒・2秒の比較はチェックポイントを変えず入力更新間隔だけを変更した。全通話オフラインは同じWhisper重みを使用するが、標準Whisper復号、内部最大30秒窓、前文脈利用、外部VADなしであり、ストリーミングとの差を入力間隔だけに帰属できない。0.5秒のCERと実時間応答遅延を混同しない。詳細な集計と再評価スクリプトは[入力間隔別CERのPR](https://github.com/Quick-119/call119-streaming-asr/pull/7)にある。

模擬TTS通報30件では現行モデルの0.5秒CERは**4.88%**。制御された声・台本での値であり、実通報の20.268%を代替する指標にはならない。

## 3. これまでに試した主な方向

異なる時期のGold版、データ集合、音声長、入力間隔のCERは横並びのランキングにしない。次の表は、各実験が何を確かめ、何が残ったかをまとめたもの。

| 方向 | 試したことと分かったこと | 現行への位置付け |
|---|---|---|
| 初期のWhisper/LoRA適応 | large-v3-turbo系でencoder/decoderのLoRA、教師品質層、rank、prefix、弱いSpecAugmentを比較。擬似ラベル上では広いTier A+B教師が有利だった一方、prefixと追加augは悪化。 | 教師選別と実通報Goldでの採用判定を重視する根拠。turbo系のCERを現行large-v3へ直接比較しない。 |
| 医療語の合成音声 | TTSのみの追加学習で医療語完全一致は48%→82%になったが、小規模既存119評価CERは32.34%→34.81%へ悪化。実119音声の再投入で一部回復。後続ではdecoder限定更新が実119の保持に有利な場面もあった。 | 専門語の改善と汎用通報の悪化を同時に監視する必要がある。現行重みへ医療TTS候補を統合していない。 |
| 人手Gold適応と0.5秒化 | `c37`系統を選び、短い入力に合わせて厳密なVAC起動を実装。人手1,419件候補から学習した初回の追加モデルは、独立25通話で旧`c37`の19.042%に対して19.065%で改善せず。 | データ量を増やすだけでは十分でない。`c37`を後続の比較起点にした。 |
| 学習窓と更新範囲 | 人手窓の品質選別、q/v継続、q/k/v/out/MLP拡張、旧教師再投入、学習率低下、重み補間・平均を試した。開発97通話では良い候補も、温存27通話で重み平均は31.128%→33.257%に悪化。 | 窓境界と未知区間、挿入・脱落の偏り、少数通話の大退行が採用の障害。 |
| 自動教師→人手教師 | GPT-4o品質選別、全文一致度選別、1窓/最大3窓/全適格窓、広い教師、低学習率、人手のみ、人手再投入、混合学習を比較。現行の「品質選別・全適格窓→人手再投入」が開発で最良。自動教師と人手高品質窓を同時混合した条件は開発CER21.161%で旧`c37`より悪化。 | **現行チェックポイントを採用**。単純な教師追加や混合比の変更は改善策として未確認。 |
| 東京住所の専門適応 | 公的町字から作った合成住所の学習で住所CERは改善したが、実通報の難しい27通話で悪化し、複数候補を棄却。交差注意Q/V差分を10%だけ適用した後続候補は過去126通話で20.268%→20.239%。 | 小幅な探索成果。実際の東京119通報住所の独立Gold評価がなく、汎用改善の確証ではない。 |
| 推論間隔とオフライン | 現行重みで0.5秒、1秒、2秒、全通話オフラインを比較。評価用126通話では1秒が最も低CER。 | 遅延・同時通話数とのトレードオフを次に実測する。新しい学習は不要。 |
| 正規表現後処理 | 34規則候補を個別検証し、文脈を限定した規則を選択。非重複の旧モデル実通報329通話では誤り54,958→54,936、悪化通話0。現行モデルの模擬30通話では150→137。 | **現行モデルの実通報126通話での改善量は未測定**。表記の一律変換はGold表記と衝突し得る。 |

## 4. 現在の誤りは何か

### 実通報で確定している内訳

| 現行重み・評価用126通話 | 置換 S | 脱落 D | 挿入 I | 合計誤り | CER |
|---|---:|---:|---:|---:|---:|
| 0.5秒入力 | 6,737 | 7,111 | 7,500 | 21,348 | 20.268% |
| 1秒入力 | 6,226 | 7,381 | 7,104 | 20,711 | 19.663% |
| 2秒入力 | 6,437 | 8,004 | 6,701 | 21,142 | 20.072% |
| 全通話オフライン | 5,950 | 4,748 | 11,062 | 21,760 | 20.659% |

入力間隔を長くすると挿入は減る傾向があるが、2秒では脱落が増えて1秒より総誤りが多い。オフラインは脱落が少ない一方、挿入が大きく増えた。挿入の中身をすべて「幻覚」と断定することはできない。Gold不明区間の扱い、重複、終端処理の違いも含めて、音声位置と出力を照合する必要がある。

評価群の差も大きい。0.5秒の`test_old`24通話18.770%、`test_new`25通話18.295%、`test_fresh`50通話18.622%に対し、`test_fresh2`27通話は**27.125%**。最後の27通話は高品質な学習窓を作れなかった通話に偏っており、一般的な通話分布を代表しない可能性がある。ただし、現行モデルが難しい条件で弱いという警告にはなる。原因が低SNR、重畳発話、音声区間境界、地域語彙、話者属性のどれかは、現時点の集計だけでは特定できない。

### 語句レベルの例：公開済みの**模擬**119通報から

現行モデルの実通報評価は通話ごとの誤り数と出力SHA-256を保持し、文字出力本文は保持していない。そのため、次の具体例は現行モデルによる**模擬TTS30件**の誤り棚卸しから採った。実通報で同じ語を誤ったという主張ではない。

| 型 | 正解 → 出力の例 | R&D上の意味 |
|---|---|---|
| 数字・住所表記 | `二丁目`→`2丁目`、`百二号室`→`102号室` | 音として同じでも現行CERでは誤り。数字正規化の評価規約と、表示用表記を分ける必要がある。 |
| 近音語・専門語 | `二階`→`2体`、`同僚`→`糖尿`、`河川敷`→`先時期` | 音響・文脈双方が曖昧。住所・建物・傷病の重要スロットでは文字CERに加えて意味上の重大度を測る。 |
| 漢字・仮名の選択 | `けが`→`怪我`、`けいれん`→`痙攣` | 正規化後も文字列が違う。表記統一の一律適用は別のGoldと衝突する。 |
| 脱落・挿入 | 短い助詞や応答の欠落、境界での余分な文字 | 通話全体の確定タイミング、VAD境界、重畳発話の調査が必要。 |

この棚卸しは94個の差分群で、数字表記50、漢字・仮名表記14、語彙・音韻等16、脱落11、挿入3。これは`SequenceMatcher`による**模擬データの差分群数**であり、実通報のCER誤り文字数や発生率ではない。

## 5. なぜ改善の余地が残るのか：検証済みの事実と仮説

1. **教師の量と品質が両立していない。** 自動教師だけでは旧`c37`から7.594ポイント悪化した。GPT-4o/Chirp3の一致度と人手誤りには強い相関があり、低品質教師の混入は有力な説明。ただし、忘却や学習率の寄与と切り分けた因果実験ではない。
2. **28秒前後の学習窓と本文の境界がずれる可能性。** 過去の人手窓では、窓への文字割当がASRアンカーに依存し、不明区間に接する窓もあった。今回も「人手全文が正しい」と「個々の音声窓の教師が正しい」は別。境界を手作業で監査した窓だけで再実験する価値がある。
3. **学習目標と利用時の失敗が一致しない。** teacher-forced損失は28秒程度の窓で最適化し、利用時は0.5秒刻みで途中確定した文字を積み上げる。推論間隔だけでCERが20.268%→19.663%と動く事実は、重み以外のストリーミング動作が効いている証拠。ただし、それだけでattention headやVADを原因と確定できない。
4. **挿入・脱落の偏りが候補ごとに大きい。** 厳格窓だけの学習で挿入が減って脱落が増え、拡張LoRAでは逆の傾向を示した。重み平均で開発群が良くても、別の難しい27通話では単一通話の挿入が大きく増えて棄却した。平均CERだけでは安全性を把握できない。
5. **住所・数字・医療語は全文CERと別の目的。** 合成東京住所を良くした重みが実通報の難例を悪化させた。模擬通報では数字と表記差が目立つ。所在地、番地、年齢、傷病、否定表現などは全文CERに加えて成分別の正誤と重大度が必要。
6. **評価の独立性と遅延の測定が不足。** 主要126通話は今回の学習から除外したが、以前の研究で結果を見ている。東京住所候補の30文字差や入力間隔の最適値を固定するには、新規の未接触通話で再評価する必要がある。多数同時通話時の発話→表示遅延もCERとは別に測る。

## 6. R&Dに渡したい次の実験順

1. **採用重みを固定し、0.5/1/2秒の品質・遅延曲線を同じ通話で測る。** CER、S/D/I、発話→初回表示、確定までの遅延、20同時通話のp95、GPUメモリをセットで比較する。現行の1秒19.663%が未接触集合でも再現し、運用上の遅延条件を満たすかが最初の問い。
2. **実通報の誤り監査を小さな未接触集合で実施する。** 許可された環境内で、音声・Gold・出力を時刻付きで人手照合し、SNR、話者重畳、VAD開始/終了、発話速度、長い無音、地名・番号・傷病を注記する。公開資料には再集計したカテゴリ数と匿名化例だけを出す。これにより「挿入」のうち反復・無音幻覚・表記差・Gold不明区間近傍を分けられる。
3. **高品質な教師窓の境界を検証してから学習を再試行する。** 手検証した短い窓と現行窓を同量で比較し、自動教師品質、初期重み、人手再投入率、学習率を一度に変えない。開発CERに加え、未接触通話と最大単一通話退行を事前ゲートにする。
4. **重要情報を別指標で守る。** 住所の町字・番地、年齢、電話番号、傷病、否定の成分別正答率を設計し、全文CERを悪化させない制約と併用する。東京住所向け候補は実際の東京119通報住所の人手Goldで検証してから再選定する。
5. **後処理は限定的な規則から段階的に検証する。** 文脈が明確な規則のみ、採用モデルの実通報で通話別の悪化件数と全体CERを測る。旧モデル329通話や模擬30件の改善値を、そのまま現行モデルの改善値として報告しない。
